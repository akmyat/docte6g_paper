The overall architecture of the proposed integrated simulation framework is depicted in Figure \ref{fig:system_architecture}.
The proposed integrated simulation framework follows a layered design in which ns-3 remains the primary discrete-event simulator while Sionna RT is embedded as an environment-aware ray tracing engine \cite{pybind11,ns3sionna,sionna,sionnart}.
The architecture preserves the mature protocol, traffic generation, and scheduling capabilities of ns-3 and Sionna RT handles ray tracing to provide a site-specific propagation channel model, with GPU acceleration for computationally intensive operations.

    \centering
    \includegraphics[width=\linewidth]{images/SionnaRT_System_Architecture.drawio.png}
    \caption{Architecture of the integrated simulation framework. }
    \label{fig:system_architecture}
\end{figure}

The application layer generates user-defined traffic between UEs and the gNB.
Traffic types include video streaming, social media, gaming, FTP, and VoIP, enabling simulation of diverse workload scenarios.

The middle layer (shown in green) contains the ns-3 network stack, which handles node management, mobility, routing, scheduling, and MAC operations for the chosen protocol standard (Wi-Fi 802.11ax or 5G NR).
When a packet is generated, it passes through the protocol stack until it reaches the wireless medium, at which point ns-3 invokes \texttt{PropagationLossModel} and \texttt{PropagationDelayModel} to obtain path loss, transmission delay, and channel response.

When \texttt{PropagationLossModel} or \texttt{PropagationDelayModel} is invoked, the Sionna RT engine computes environment-aware channel parameters (path loss, propagation delay, and arrival and departure angles) for the requested transmitter–receiver pair.
Issuing a full ray tracing query on every packet event is computationally expensive and would dominate simulation runtime.
The framework addresses this through two complementary mechanisms: a coherence-distance cache that reuses recently computed parameters for spatially close positions, and adaptive virtual receiver pre-computation that pre-populates the cache with channel parameters for predicted future node positions.
On each query for a link $(p_{tx}, p_{rx})$, the cache layer computes the spatial displacement between the current positions and those stored in the cache entry.
If the displacement is below the coherence distance $d_\mathrm{coh}$, the cached parameters are returned directly.
Otherwise, the Sionna RT engine is invoked and the cache is updated with the newly computed parameters.
Algorithm~\ref{alg:cache_query} formalizes this lookup procedure.

\begin{algorithm}[t]
    \caption{Propagation Query with Coherence Cache}
    \label{alg:cache_query}
    \begin{algorithmic}[1]
        \REQUIRE transmitter position $p_{tx}$, receiver position $p_{rx}$, coherence distance $d_\mathrm{coh}$
        \ENSURE channel parameters $\mathbf{H}$
        \STATE $\mathit{key} \leftarrow \mathrm{hash}(p_{tx},\, p_{rx})$
        \IF{$\mathit{key} \in \mathrm{cache}$}
        \STATE $(\mathbf{H}_c,\, p_{tx}^s,\, p_{rx}^s) \leftarrow \mathrm{cache}[\mathit{key}]$
        \STATE $d \leftarrow \|p_{tx} - p_{tx}^s\| + \|p_{rx} - p_{rx}^s\|$
        \IF{$d < d_\mathrm{coh}$}
        \RETURN $\mathbf{H}_c$ \hfill \COMMENT{cache hit}
        \ENDIF
        \ENDIF
        \STATE $\mathbf{H} \leftarrow \mathrm{SionnaRT.ComputePaths}(p_{tx},\, p_{rx})$ \hfill \COMMENT{cache miss}
        \STATE $\mathrm{cache}[\mathit{key}] \leftarrow (\mathbf{H},\, p_{tx},\, p_{rx})$
        \RETURN $\mathbf{H}$
    \end{algorithmic}
\end{algorithm}

To further reduce cache misses, the framework proactively pre-populates the cache with channel parameters for predicted future node positions.
Given each node's current position $p_i$ and velocity $v_i$, a set of future positions is computed over a discrete set of look-ahead intervals $\{\Delta t_k\}$.
These predicted positions are inserted into the Sionna RT scene as \emph{virtual receivers} alongside the real receivers.
A single batched ray tracing call then computes paths for all positions simultaneously, and the resulting parameters are stored in the cache.
Algorithm~\ref{alg:virtual_rx} describes this pre-computation step.

\begin{algorithm}[t]
    \caption{Adaptive Virtual Receiver Generation}
    \label{alg:virtual_rx}
    \begin{algorithmic}[1]
        \REQUIRE node positions $\{p_i\}_{i=1}^{N}$, velocities $\{v_i\}_{i=1}^{N}$, look-ahead intervals $\{\Delta t_k\}_{k=1}^{K}$, transmitter position $p_{tx}$
        \ENSURE cache pre-populated for predicted future positions
        \STATE $P_\mathrm{virtual} \leftarrow \emptyset$
        \FOR{each node $i \in \{1, \ldots, N\}$}
        \FOR{each interval $\Delta t_k \in \{\Delta t_k\}$}
        \STATE $p_\mathrm{future} \leftarrow p_i + v_i \cdot \Delta t_k$
        \STATE $P_\mathrm{virtual} \leftarrow P_\mathrm{virtual} \cup \{p_\mathrm{future}\}$
        \ENDFOR
        \ENDFOR
        \STATE $P_\mathrm{all} \leftarrow \{p_i\} \cup P_\mathrm{virtual}$ \hfill \COMMENT{real + virtual receivers}
        \STATE $\mathbf{H}_\mathrm{all} \leftarrow \mathrm{SionnaRT.ComputePaths}(p_{tx},\, P_\mathrm{all})$ \hfill \COMMENT{single batched call}
        \FOR{each $p_j \in P_\mathrm{all}$}
        \STATE $\mathrm{cache}[\mathrm{hash}(p_{tx},\, p_j)] \leftarrow (\mathbf{H}_\mathrm{all}[j],\, p_{tx},\, p_j)$
        \ENDFOR
    \end{algorithmic}
\end{algorithm}

However, ns-3 cannot directly call the Sionna RT engine, as the two components are written in different programming languages.
A wrapper class is therefore introduced to bridge ns-3 and the Sionna RT engine.

The bottom layer hosts the Sionna RT engine, which performs the physical ray tracing computation.
Before simulation begins, the engine is initialized with radio propagation parameters, antenna configuration, and the 3D scene file name passed from the ns-3 side.
During simulation, the path solver computes path loss, time of arrival, angle of arrival, and angle of departure for each requested receiver position by tracing rays through the 3D environment \cite{sionnart}.
These computations execute on the GPU, and the results are returned to the cache layer via the wrapper class.

All experiments are conducted on an Asus Ascent GX10 AI supercomputer equipped with an NVIDIA GB10 Grace Blackwell Superchip: a 20-core Arm-based NVIDIA Grace CPU paired with an NVIDIA Blackwell GPU, 128~GB of unified LPDDR5x memory, and NVIDIA ConnectX-7 networking.
