\subsection{Sionna Propagation Cache Mechanism}
\label{sec:sionna-cache-mechanism}

\subsubsection{Displacement-Based Cache Validity}
\label{subsec:cache-validity}

The cache exploits spatial coherence: when a node moves only a small distance from its last traced position, channel parameters change negligibly.
Cache validity is therefore determined by spatial displacement rather than elapsed time.

The cache stores a record for each transmitter–receiver pair in the ns-3 simulation.
Each cache entry is indexed by a canonical unordered node pair,
\begin{equation}
    \kappa(a,b)=\left(\min(I_a,I_b),\max(I_a,I_b)\right),
\end{equation}
where $I_a$ and $I_b$ are ns-3 node identifiers.
Each entry stores the node positions $\mathbf{x}_a^0$ and $\mathbf{x}_b^0$, path loss, transmission delay, channel frequency response (CFR), and line-of-sight (LoS) state.

The distance between Tx and Rx is calculated using
\begin{equation}
    d_{a,b}^0=\left\|\mathbf{x}_a^0-\mathbf{x}_b^0\right\|_2 ,
\end{equation}
and the validity radius is given by
\begin{equation}
    \Delta_{a,b}=
    \max\left(
    \Delta_{\min},
    \alpha \frac{0.886 d_{a,b}^0}{N_{\mathrm{tx,col}}}
    \right).
\end{equation}
where $\alpha$ is set to $0.4$ and $\Delta_{\min}$ is set to $0.1$ m as default values.

On each propagation query for a Tx–Rx pair, the current positions $\mathbf{x}_a(t)$ and $\mathbf{x}_b(t)$ are compared against the positions stored at trace time.
A valid cache entry exists if
\begin{equation}
    \left\|\mathbf{x}_a(t)-\mathbf{x}_a^0\right\|_2 < \Delta_{a,b}
    \quad\mathrm{and}\quad
    \left\|\mathbf{x}_b(t)-\mathbf{x}_b^0\right\|_2 < \Delta_{a,b}.
\end{equation}
If both inequalities are satisfied, the cached parameters are returned directly.
Otherwise, the lookup is a cache miss and the snapshot is refreshed.

\subsubsection{Snapshot Refresh}
\label{subsec:cache-refresh}

When a cache miss occurs, the framework refreshes all Tx–Rx pairs rather than only the affected link.
First, the positions of every node that uses \texttt{SionnaMobilityModel} are synchronized into the Python Sionna scene.
A single batched ray tracing call is then issued for all Tx–Rx pairs by invoking \texttt{perform\_calculation} in \texttt{sionnart.py}.
When the computation completes, the returned records are deserialized via pybind11 and inserted as new cache entries.
For each record, the cache stores
\begin{equation}
    \left(
    \tau_{a,b},\,
    L_{a,b},\,
    \mathbf{h}_{a,b},\,
    \mathbf{H}_{a,b},\,
    \mathbf{f},\,
    \mathrm{LoS}_{a,b},\,
    \mathbf{x}_a^0,\,
    \mathbf{x}_b^0,\,
    \Delta_{a,b}
    \right),
\end{equation}
where $\tau_{a,b}$ is delay, $L_{a,b}$ is path loss, $\mathbf{h}_{a,b}$ is the
scalar CFR, $\mathbf{H}_{a,b}$ is the MIMO CFR, and $\mathbf{f}$ is the
frequency vector.
The old cache records are replaced only if the new results contain usable entries.

\subsubsection{Lookup and Fallback Behavior}
\label{subsec:cache-lookup-fallback}

ns-3 queries propagation information for each Tx–Rx pair.
For a normal link, the cache searches the canonical key, tests displacement validity, and returns the first valid entry found.
If no valid entry exists, the cache refreshes all records and retries the same lookup sequence.

In Sionna RT, links between nodes with the same radio role, such as Tx–Tx or Rx–Rx, cannot be computed.
In such cases, a dummy entry with large path loss and delay is returned instead.
If Sionna RT does not return usable data for the requested link after refresh, the cache falls back to the stochastic Friis model and constant-speed delay.

Before calling Sionna RT, the cache checks the estimated received power using the Friis model to avoid unnecessary ray tracing.
If
\begin{equation}
    P_{\mathrm{Friis}}^{\mathrm{rx}} + M
    <
    P_{\mathrm{weak}},
\end{equation}
where $P_{\mathrm{weak}}=-95$ dBm and $M=6$ dB by default, the link is treated
as too weak to justify ray tracing.
In that case, Friis loss and constant-speed delay are used directly.

\subsubsection{Derived MIMO Caches}
\label{subsec:derived-mimo-caches}

The records returned by the Sionna RT engine store the normalized element-level MIMO CFR.
However, ns-3 requires derived quantities such as port-level channels, PSD-scaled matrices, and effective post-precoding gains.
These quantities depend not only on geometry but also on antenna configuration, beamforming vectors, PSDs, and precoders.
They are computed from the element-level CFR together with ns-3-side parameters and stored as derived cache entries.

Computation proceeds as follows.
For a given beam configuration, the element-level channel is projected onto
antenna ports.
For resource block $q$, transmit port $p_t$, and receive port
$p_r$, the port-level channel has the form
\begin{equation}
    G_{p_r,p_t}[q]
    =
    \sum_{i\in\mathcal{E}_{p_r}}
    \sum_{j\in\mathcal{E}_{p_t}}
    w_{r,i}\,w_{t,j}\,
    \widetilde{H}_{i,j}[q],
\end{equation}
where $\mathcal{E}_{p_r}$ and $\mathcal{E}_{p_t}$ are the receive and transmit
element sets associated with the ports, and $w_{r,i}$ and $w_{t,j}$ are the
beamforming weights.
This port CFR is cached using antenna identifiers,
beamforming-vector hashes, port counts, and link direction.

For spectrum propagation, the port CFR is scaled by the input PSD:
\begin{equation}
    C_{p_r,p_t}[q]
    =
    \sqrt{S[q]}\,G_{p_r,p_t}[q],
\end{equation}
where $S[q]$ is the PSD value on resource block $q$. The most recent
PSD-scaled matrix is cached using a PSD hash and PSD size.

When a precoding matrix $\mathbf{W}[q]$ is provided, the effective gain per
resource block is
\begin{equation}
    g[q]
    =
    \sum_{p_r}\sum_s
    \left|
    \sum_{p_t} G_{p_r,p_t}[q] W_{p_t,s}[q]
    \right|^2 .
\end{equation}
These gains are cached using the port-CFR key, precoder hash, precoder
dimensions, and output resource-block count.
This avoids repeated beamforming and precoding reductions while the underlying propagation entry remains valid.
